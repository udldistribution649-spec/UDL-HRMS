# UDL HRMS — API Endpoint Reference

## 1. Project API Information

- Framework: FastAPI
- API prefix: `/api/v1`
- API documentation: `/docs`
- OpenAPI schema: `/openapi.json`
- Backend source: `backend/app/`

Local development URL is commonly `http://127.0.0.1:8000`.

## 2. Root and Health Endpoints

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/` | API root information |
| GET | `/health` | Backend health check |

## 3. Authentication

| Method | Endpoint | Purpose |
|---|---|---|
| POST | `/api/v1/auth/login` | User login |

Source: `backend/app/api/v1/endpoints/auth.py`

Security requirements:
- Email OTP two-factor authentication for all users.
- Session timeout: 15 minutes.
- Password hashing; never store plaintext passwords.
- Must-change-password support.
- Sensitive actions must be audited.

Document additional authentication endpoints only after verifying them in the live OpenAPI schema.

## 4. Employee Endpoints

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/api/v1/employees/` | List employees |
| GET | `/api/v1/employees/{employee_id}` | Retrieve employee details |

Source: `backend/app/api/v1/endpoints/employees.py`

Employee rules:
- Employee code must contain numeric characters only.
- Maximum employee code length: 20 characters.
- Existing imported employee codes must be preserved.
- New employee codes are generated by the backend.
- Rejoining employees receive a new employee code.
- Reporting manager code `0` represents a root employee and maps to NULL.

Verify all other employee methods against the current OpenAPI schema.

## 5. Department Manager Scope

| Method | Endpoint | Purpose |
|---|---|---|
| POST | `/api/v1/department-manager-scopes/requests` | Submit scope request |
| POST | `/api/v1/department-manager-scopes/requests/{request_id}/decision/{decision}` | Approve or reject request |
| POST | `/api/v1/department-manager-scopes/requests/{request_id}/execute` | Execute approved request |
| GET | `/api/v1/department-manager-scopes/` | List manager scopes |

Source:
- `backend/app/api/v1/endpoints/department_manager_scopes.py`
- `backend/app/services/department_manager_scope_request_service.py`
- `backend/app/services/department_manager_scope_service.py`

Workflow:
1. HR Admin initiates assignment, change, or revocation.
2. Director approval is optional/configurable.
3. Self-approval is prohibited.
4. HR Admin cannot directly activate a scope.
5. Only an approved and authorized request can be executed by Super Admin/IT.
6. Department Managers can access only their assigned departments and sub-departments.

## 7. Roles and Access

| Role | Responsibility |
|---|---|
| Super Admin | IT operations and approved technical execution |
| HR Admin | HR administration within approved policy |
| Director | Company policy and approval where configured |
| Department Manager | Assigned department/sub-department operations |

Super Admin is an IT role, not unrestricted business-policy authority.

PF Loan, PF Withdrawal, and Company Loan have separate approval chains.

## 8. Endpoint Documentation Standard

Whenever a new endpoint is implemented, document:
- HTTP method and exact URL.
- Purpose and business workflow.
- Required role and authorization scope.
- Request schema and required fields.
- Response format.
- Possible error responses.
- Audit logging behavior.
- Whether retrying the operation is safe.
