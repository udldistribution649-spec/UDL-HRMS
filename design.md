# UDL HRMS — Application Design

## 1. Product Overview

UDL HRMS is a locally hosted, company-scoped Human Resource Management System with Employee Self-Service (ESS).

It is inspired by HRMS product patterns. Odoo is not installed or used.

Main objectives:
- Employee master management.
- Organization management.
- Attendance and leave management.
- Payroll and Provident Fund management.
- Employee Self-Service.
- Role-based security and approvals.
- Audit history.
- Controlled data import and backup.

## 4. Core Design Principles

1. Preserve existing employee and business data.
2. Do not perform destructive database changes without approval.
3. Validate data before database writes.
4. Enforce authorization on the backend.
5. Follow least-privilege access.
6. Maintain audit history for sensitive operations.
7. Preserve historical employee assignments.
8. Never invent missing employee data.
9. Use Alembic for database schema changes.
10. Test changes before applying them to the main database.

## 5. Roles and Governance

### Super Admin
- IT Developer/IT Manager responsibility.
- Approved technical execution.
- Session administration.
- Server-side backup operations.
- Not unrestricted business-policy authority.

### HR Admin
- HR operations.
- Employee administration.
- Role assignments within approved company policy.
- Initiates manager-scope requests.

### Director
- Defines company authority and policy.
- Approval is optional/configurable where specified.

### Department Manager
- Access limited to assigned department/sub-department.
- Approves or rejects permitted departmental applications.

No user may approve their own request.

## 6. Security Requirements

- Email OTP 2FA for all users.
- 15-minute session timeout.
- Secure password hashing.
- Must-change-password support.
- Audit logs for sensitive actions.
- Super Admin session viewing and termination.
- Daily server-only backups.
- Backup retention: 30 days.
- Encrypted source database credentials.
- Read-only access for external source database connections.

Implementation must be verified before marking a requirement complete.

## 7. Employee and Organization Design

Organization structure:
- Location
- Division
- Department
- Sub-Department
- Designation

Employee rules:
- Numeric employee codes, maximum 20 characters.
- Preserve imported employee codes.
- New codes generated by backend.
- Rejoining employees receive new codes.
- Manager code `0` maps to NULL for root employees.
- Department codes unique within their Division.
- Sub-Department codes unique within their Department.
- Resigned employees remain as inactive records.
- Missing joining dates remain blank.

Employee assignment changes must preserve historical information and effective dates.

## 8. Employee Import Design

Import process:
1. Read source Excel/database.
2. Validate employee codes.
3. Validate duplicate records.
4. Validate reporting managers.
5. Validate organization references.
6. Display preview and error counts.
7. Import the complete valid batch atomically.
8. Roll back on fatal errors.
9. Preserve original employee codes.
10. Record import history and audit information.

Corrected imports must not silently overwrite existing records.

Historical payroll, attendance, leave, and PF imports require separate validation and reconciliation.

## 9. ESS Design

- Employees can access only their own information.
- Login through Employee Code and password.
- Forgot-password workflow.
- Profile changes requiring approval must follow manager/HR approval before updating employee master data.

## 10. Payroll, Leave and PF

Business rules are maintained in `Rules.md`.

Important agreed rules:
- Financial year: July to June.
- Leave baseline: Annual Leave 15, Sick Leave 10, Casual Leave 10.
- Contractual and Intern employees are PF-ineligible.
- PF contribution follows confirmation date and eligible salary/work-day rules.
- Zakat: 1.25% on eligible withdrawal/final settlement.
- Standard PF withdrawal limit: 70%, subject to special approval.
- PF loan repayment: maximum 48 months.
- Payroll uses current-month salary context and previous-month attendance.

Do not change financial calculations without confirming the business rules.

## 11. Development and Deployment

- Development DB: `udl_hrms_db`
- Test DB: `udl_hrms_test_db`
- PostgreSQL local hosting is the current deployment direction.
- Never commit `.env`, database backups, employee exports, passwords, or encryption keys.
