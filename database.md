# UDL HRMS — Database Design

## 1. Database Platform

- Database: PostgreSQL 18
- ORM: SQLAlchemy
- Migration tool: Alembic
- Main database: `udl_hrms_db`
- Test database: `udl_hrms_test_db`
- Application DB user: `udl_hrms_app`

Development and test databases must remain separate.

Never run destructive test operations against the main database.

## 2. Database Configuration

Important backend files:
- `backend/app/core/database.py`
- `backend/app/core/config.py`
- `backend/alembic.ini`
- `backend/migrations/env.py`

Environment files contain secrets and must never be committed to Git.

## 5. Employee Data Rules

- Employee code is numeric and maximum 20 characters.
- Preserve legacy employee codes during imports.
- New employee codes are generated by the backend.
- Rejoining employees receive a new employee code.
- Reporting manager code `0` maps to SQL NULL for a root employee.
- Non-root employees must have a valid reporting manager.
- Resigned employees remain as inactive records.
- Missing joining dates must remain blank.
- Employee assignment changes preserve effective-dated history.

## 6. Organization Data Rules

Hierarchy:
- Location
- Division
- Department
- Sub-Department

Uniqueness:
- Department code is unique within its parent Division.
- Sub-Department code is unique within its parent Department.

Do not incorrectly impose global uniqueness on parent-scoped organization codes.

## 7. Security and Scope Data

- User records are separate from employee master records, linked according to implemented model relationships.
- Sensitive operations require audit history.
- Manager scopes limit access to assigned departments/sub-departments.
- Scope requests and active scopes are separate records/concepts.
- A request must not activate a manager scope before the authorized execution workflow.

## 8. Import Integrity

1. Read source data without modifying it.
2. Validate required fields and formats.
3. Validate duplicate employee codes.
4. Validate manager references.
5. Validate organization references.
6. Convert source manager code `0` to NULL.
7. Preserve employee codes.
8. Keep missing values blank.
9. Preview validation results before import.
10. Commit the complete batch in one transaction.
11. Roll back the entire batch if a fatal error occurs.
12. Record import history and reconcile totals.

Do not silently overwrite existing records during corrected re-imports.

## 9. Data Protection

Never commit:
- `.env` or `.env.test`.
- Passwords, JWT secrets, OTPs, or encryption keys.
- Database dumps and backups.
- Employee Excel/CSV exports.
- Real employee personal information.

External source database credentials must be encrypted at rest and access restricted. Use read-only database credentials for source connections.

## 10. Safe Migration Procedure

From `D:\UDL-HRMS\backend`:

```powershell
.\.venv\Scripts\Activate.ps1
alembic current
alembic heads
alembic history
```

Before applying a migration:
1. Confirm the selected database environment.
2. Take and verify an appropriate backup.
3. Inspect the generated migration.
4. Review constraints, foreign keys, indexes, and nullability.
5. Test on the test database first.
6. Run the test suite.
7. Apply to the main database only after explicit approval.

Typical commands, only after verifying the target environment:

```powershell
alembic revision --autogenerate -m "describe_schema_change"
alembic upgrade head
```

Never manually drop tables or run downgrade as a shortcut.
